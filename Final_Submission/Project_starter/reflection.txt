For my design decision, I decided to just use local python functions with the @tool decorator for the knowledge base and the code sandbox. I didn't want to make them into separate lambda functions because it seemed like too much extra work for things that don't need to change any data in the backend. It kept the API gateway strictly for the important stuff like tracking orders and refunds.

The biggest challenge I faced was that the Strands SDK got updated and broke the starter code. The instructions told us to use registry.register() but that didn't work anymore. I had to change it to registry.add_callback(). On top of that, the message objects changed into dictionaries. My MemoryHook kept crashing with AttributeError. I had to rewrite the memory parsing part to check if the message was a dictionary first before trying to pull the text out. It took me a long time to figure out. 

If this agent was going into a real production environment, the first thing I would change is the security. Right now the AWS keys are just sitting in the terminal environment variables. We would need to give it a proper IAM role. Also I would try to add some caching so we don't spend too much money on tokens when people ask the same questions over and over.
