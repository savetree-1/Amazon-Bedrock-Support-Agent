# Project Reflection: AI Customer Support Agent

## Design Decision
To optimize latency and architecture complexity, I decided to handle the Bedrock Knowledge Base search and the Code Interpreter Sandbox directly within the Strands `Agent` initialization via local Python functions decorated with `@tool`, rather than offloading them as separate Lambda functions. This architectural choice simplified the MCP Gateway routing. The Gateway was strictly reserved for sensitive, state-modifying backend API operations (`order-tracker` and `refund-processor`). This hybrid approach prevents unnecessary network hops and reduces overall execution time for stateless, read-only customer requests.

## Challenge Encountered
One of the most significant technical challenges was navigating undocumented breaking changes in the Strands SDK API during development. Specifically, the `HookRegistry.register()` method was deprecated and replaced with `add_callback()`. Furthermore, the internal message schema migrated from object-attributes to dictionary-based representations. This completely broke the `MemoryHook` event handlers, causing `AttributeError` exceptions when retrieving cross-session context. To overcome this, I utilized Python’s `inspect` module to dynamically extract the updated method signatures. I then rewrote the memory parsing logic, implementing robust `isinstance(msg, dict)` checks and `get()` fallbacks to safely extract roles and contents, restoring the long-term memory functionality.

## Production Consideration
Before deploying this agent to a real-world, high-traffic production environment, security and cost optimizations must be addressed. Currently, AWS credentials are provided as static environment variables. In a true production deployment, the agent should be natively hosted on the Bedrock AgentCore Runtime, utilizing a dedicated IAM Role with the principle of least privilege. Additionally, to manage API costs and prevent LLM hallucinations, I would implement structured output validation (using Pydantic) for tool responses, and enable prompt caching to minimize token consumption during extended, multi-turn customer support conversations.
